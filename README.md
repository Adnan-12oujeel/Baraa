# دعوة زفاف براء وكريمته ✨

موقع عربي ثابت بتصميم فاخر يعمل **HTML + CSS + JavaScript فقط** — دون React أو npm أو أي إطار عمل.

## تشغيل الموقع محليًا

افتح `index.html` مباشرة في المتصفح، أو شغّل خادمًا محليًا بسيطًا (اختياري) من داخل المجلد:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000`.

## نشره على GitHub Pages

1. أنشئ **Repository** جديدًا على GitHub، مثل `wedding-invitation`، واجعله عامًا إذا أردت موقعًا عامًا.
2. ارفع **محتويات هذا المجلد** إلى جذر المستودع (`index.html` و`style.css` و`script.js` و`assets/`، وليس المجلد الحاوي لها فقط).
3. افتح `Settings → Pages` في مستودع GitHub.
4. عند `Build and deployment` اختر `Deploy from a branch`، ثم اختر `main` و`/(root)`، واضغط `Save`.
5. سيكون الرابط غالبًا `https://USERNAME.github.io/wedding-invitation/` (استبدل `USERNAME` باسم حسابك والمستودع باسمه الفعلي).

تدعم الصفحة النشر في جذر المشروع أو تحت مسار المستودع لأن المسارات المستخدمة **نسبية** (`assets/...`). لا حاجة إلى npm أو بناء Build.

## تعديل المحتوى

- **التاريخ والوقت، اسم صالة الرجال، صالة النساء وروابط الخرائط، Supabase:** افتح `script.js` وعدّل كائن `WEDDING_CONFIG` في أعلى الملف.
- **أسماء العروسين والنصوص والآية:** افتح `index.html`. عدّل أيضًا بيانات العنوان والوصف وتاريخ الحدث في النص الظاهر إذا غيّرت المناسبة؛ قيمة `weddingDate` في JavaScript تخص العداد والتقويم.
- **الألوان والخطوط والحركات:** افتح `style.css`.
- **صور العروسين:** استبدل `assets/hero.webp` و`assets/couple.webp` بصور العروسين إن أردت. الصور المرفقة **صور فنية تمثيلية** وليست للعروسين الحقيقيين.

### روابط الصالات

```js
menVenue: {
  name: 'صالة البعاج',
  address: 'مدينة أعزاز، سوريا',
  mapUrl: 'https://maps.app.goo.gl/PUT_ACTUAL_VERIFIED_LINK_HERE'
},
womenVenue: {
  name: 'اسم صالة النساء',
  address: 'العنوان الصحيح',
  mapUrl: 'https://maps.app.goo.gl/PUT_ACTUAL_VERIFIED_LINK_HERE'

```

هذه روابط **لشرح مكان التعديل فقط**؛ يجب وضع الروابط الصحيحة الحقيقية قبل النشر. طالما `mapUrl: ''` فلن يظهر زر مضلل. الموقع لا يخمّن موقع الصالة.

## تهاني الضيوف: كيف أجعلها تعمل للجميع؟

GitHub Pages استضافة ملفات ثابتة، **لا تملك قاعدة بيانات**. صُمم النموذج في وضعين:

- **دون إعداد:** تحفظ التهاني محليًا داخل متصفح الزائر باستخدام `localStorage`. تظهر فقط لهذا الزائر على نفس الجهاز (وضع معاينة، مع إشعار صريح للزائر بذلك).
- **مع Supabase:** تُحفظ التهاني فعليًا في قاعدة بيانات واحدة، وتبقى غير منشورة إلى أن يعتمدها صاحب الدعوة. بعد الاعتماد تظهر للجميع تلقائيًا عند تحميل القسم/الصفحة.

### تفعيل Supabase (اختياري)

1. أنشئ مشروعًا في [Supabase](https://supabase.com/).
2. افتح `SQL Editor` والصق محتوى `supabase-setup.sql` وشغّله مرة واحدة.
3. من `Project Settings → API` أو `Connect` (حسب واجهة Supabase) انسخ عنوان المشروع والمفتاح العام **anon/publishable فقط**.
4. ضعهما في أعلى `script.js`:

```js
supabase: {
  url: 'https://YOUR_PROJECT.supabase.co',
  anonKey: 'YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY'
}
```

5. التهاني الجديدة تأتي `approved = false`. للموافقة افتح Supabase → `Table Editor` → `wedding_wishes` وغيّر `approved` إلى `true` للرسائل المناسبة.
6. يمكن للزوار قراءة التهاني المعتمدة فقط. سيظهر للمُرسل إشعار بأن تهنئته وصلت وبانتظار المراجعة.

> **مهم:** لا تضع `service_role` أو أي مفتاح سري في موقع GitHub Pages. المفتاح العام مرئي وهذا طبيعي عند تفعيل Row Level Security. قم بتشغيل حماية إضافية من الرسائل المزعجة (CAPTCHA أو معدل طلبات عبر Edge Function) إذا صار الموقع متاحًا لشريحة كبيرة. سياسات RLS هنا تمنع الزائر من اعتماد الرسائل أو قراءة غير المعتمد منها.
